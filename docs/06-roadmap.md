## 進め方の原則

1. **テストネットで再現できない機能は実装しない**（実装 → 検証の順序を守る）
2. **表示できないものには署名しない**（clear signing を後回しにしない）
3. **秘密は常に一時的**（永続化を前提とした設計変更をしない）
4. 迷ったら、既存の実装（SeedSigner / Krux / Trezor）と**バイト単位で比較**して決める
