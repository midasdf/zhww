## 2. 選定理由と注意点

### 2.1 なぜ Pi Zero 2 W ではなく Pi Zero 1.3 なのか

Pi Zero 2 W は高速だが **Wi-Fi / Bluetooth を内蔵**している。エアギャップを設計原則に置く以上、無線を持たない Pi Zero 1.3 が第一候補となる。SeedSigner も「Wi-Fi/BT 非搭載の 1.3 を推奨」としている。

| | Pi Zero 1.3 | Pi Zero 2 W |
|---|---|---|
| 無線 | なし（エアギャップ向き） | Wi-Fi/BT あり |
| 起動時間 | 最大 60 秒程度 | 大幅に短い |
| 開発時の快適さ | 低い | 高い |

**推奨**: 開発は Pi Zero 2 W で行い、最終構成は Pi Zero 1.3 とする。Zero 2 W を使う場合は (a) OS イメージに無線ドライバを含めない、(b) device tree で無線を無効化、(c) 可能ならアンテナを物理除去、の 3 点を実施し、**それでもハードウェアとしては無線チップが存在する**ことを脅威モデルに残存リスクとして明記する。

→ 具体的な手順と確認コマンドは [07-zero2w-setup.md](07-zero2w-setup.md) に記載している。

### 2.2 ディスプレイの選択

| 案 | サイズ | 利点 | 欠点 |
|---|---|---|---|
| A: Waveshare 1.3" LCD HAT（**既定**） | 1.3" / 240×240 | Zero の 40pin に直差し。SeedSigner の実績・筐体 STL がそのまま使える | EVM の calldata 表示はページ送りが必須 |
| B: 2.4〜3.5" SPI パネル（ILI9341 / ST7789） | 2.4〜3.5" | アドレス・金額の一覧性が高い | HAT 形状ではないためジャンパ線配線＋筐体は自作 STL |
| C: 1.3" HAT + ホスト側での確認 | — | 実装が最小 | ホストを信頼することになるため原則 2 に反する（非推奨） |

まず A で実装し、UX が苦しければ B へ移行する。配線はメス-メスジャンパで可能なため、B でも半田付けは不要。

### 2.3 カメラ

- QR 読み取りと画像エントロピー生成に使用する。
- **Pi Zero シリーズは 22pin 0.5mm の CSI コネクタ**であり、一般的な 15pin リボンは使えない。購入時に「Pi Zero 用ケーブル付き」を選ぶこと。
- カメラモジュールは基板内蔵フラッシュ等を持ち得るため、信頼できる販売元から購入し、到着後に外観を目視確認する。

### 2.4 GPIO ヘッダ

HAT を載せるには Zero 側に 40pin のピンが必要。半田付けを避けるため **ハンマーヘッダ**（打ち込み式）を使用する。圧入が不安な場合は導通をテスタで確認する。

## 3. 組立手順（無半田・目標 60 分）

1. **ハンマーヘッダの圧入** — Zero の GPIO 穴に 2×20 を真上から圧入（10 分）
2. **LCD HAT の装着** — 40pin に差し込む（1 分）
3. **カメラの接続** — CSI コネクタのロックバーを上げ、FPC を接触面方向に注意して差し込み、ロック（5 分）
4. **OS イメージの書込み** — リリースイメージを microSD に書き込み、ハッシュを検証（15 分）
5. **筐体の組立** — STL をプリントし、基板を固定（15 分）
6. **起動確認** — 給電し、ロゴ表示とメニュー表示を確認（5 分）
7. **自己テスト** — 画面・ジョイスティック・3 ボタン・カメラ・（任意で）QR 読取の動作確認

**重要**: 給電は必ず USB micro-B から行う。GPIO の 5V ピンと GND を逆接すると基板を破損する。

## 4. 検証（組立後・使用前）

| 項目 | 方法 |
|---|---|
| イメージ真正性 | 配布ハッシュと PGP 署名を PC 側で検証してから SD に書く |
| 画面・入力 | 全ボタンとジョイスティックの反応を確認 |
| カメラ | テスト用 QR（SeedQR）を読み取れるか確認 |
| 無線の不在 | OS に無線インタフェースが存在しないこと（`ip link`、`rfkill`）を確認 |
| エアギャップ | 起動後に SD を抜いても署名フローが完結することを確認 |

## 5. 保守・運用

- **ファーム更新**: SD カード経由。更新前に署名検証シーケンスを通す。
- **バッテリー運用推奨**: 電源断＝メモリ消去であるため、モバイルバッテリーで運用すると「使い終わったら電源を切る」運用が自然に定着する。
- **廃棄・譲渡**: seed を復元できる要素は残らない設計だが、使用済みの筐体・SD は再利用しない。

## 6. 販売する場合の追加要件（参考）

本 BOM は**個人利用**を前提とする。頒布・販売する場合は以下が別途必要になる。

- 無線を搭載する構成: 技適（技術基準適合証明）
- AC アダプタを同梱する場合: PSE
- 欧米向け: CE / FCC
- 暗号機能の輸出管理（公開ソースであっても米国 EAR では届出要件が生じ得る）
